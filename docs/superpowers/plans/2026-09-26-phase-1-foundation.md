# Phase 1: Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pnpm/Turborepo monorepo with a shared contracts package, a Next.js 16 API skeleton on Neon Postgres + PostGIS, the tag vocabulary, and working `GET /api/v1/vocabulary` and `GET /api/v1/config` endpoints deployed to a Vercel preview.

**Architecture:**

- `packages/shared` holds brand config, zod API contracts, error codes and messages, and the starter vocabulary; the mobile app and web app both import it as TypeScript source.
- `apps/web` is a Next.js 16 App Router app. Route handlers are thin: they call functions in `src/server/`, which use a Drizzle client over a `pg` pool.
- Migrations are generated by drizzle-kit and applied in the build pipeline against the unpooled connection string, never at app startup.

**Tech Stack:** Node 24, pnpm 10, Turborepo, TypeScript (strict), zod 4, Next.js 16, Drizzle ORM + drizzle-kit, `pg`, `@vercel/functions`, `@vercel/config`, Vitest, Docker (PostGIS 17-3.5), GitHub Actions, Vercel Pro, Neon.

**Spec:** `SPEC.md` (v2). Roadmap: `docs/superpowers/plans/2026-09-26-roadmap.md`.

## Revision 2 (user requirements, 2026-09-26, before execution)

The user added four requirements when approving the plan. They override the task text below wherever the two disagree:

1. **Standards and quality gates come first.** Task 1 now also creates `docs/standards.md`, a root `CLAUDE.md`, Prettier, ESLint (typescript-eslint `strictTypeChecked`), and knip, all run by one command: `pnpm check` (format, lint, typecheck, knip, tests). Each gate is proven to catch a deliberate violation before it's trusted. `pnpm check` must pass at the end of every task.
2. **Helpers before features.** The order is: shared contracts (Task 2), web helpers `env.ts` + `respond.ts` (Task 3), then database + test helpers (Task 4), then routes (Tasks 5–6).
3. **No dead code.** Nothing is added before something uses it. knip runs in default mode per task; CI and the end of the phase also run `knip --production`, which fails on exports used only by tests. As a result:
   - `compareVersions` / `isBelowVersion` move to Phase 5 (their first consumer is the app's forced-upgrade screen). Review Focus item 1 moves with them.
   - `TAG_CATEGORY_LABELS` moves to the first UI that shows category names.
   - `BRAND` holds only `appName`, `domain`, and the derived `siteUrl`, and lands in Task 3 with the layout that uses it. The publisher and support email arrive with Phase 4/7.
   - `ERROR_CODES` holds only codes something can return. In Phase 1 that is `server_error`. Each later phase adds its own codes with the code that returns them.
   - Default-parameter injection (`database: Db = db`, `env = process.env`) is removed; nothing passes those arguments. Tests use the real client and `vi.stubEnv`.
4. **One way to do each thing** (enforced by lint where possible, listed in `docs/standards.md`):
   - Every JSON response goes through `jsonResponse(schema, data, cachePolicy, status?)` in `respond.ts`, which parses the data through its shared zod contract (unknown keys are stripped, so internal fields can't leak). `Response.json` and `NextResponse` are banned elsewhere by lint.
   - Every route handler is wrapped in `withErrors`.
   - App code reads environment variables only through `readEnv(name)` in `src/env.ts` (lint bans `process.env` elsewhere in `src/`). Tooling (drizzle config, seed script) loads `.env.local` through one helper, `scripts/load-local-env.ts`.
   - `@/` imports inside `apps/web`; parent-relative imports (`../`) are banned by lint.
   - Tests avoid change detectors: vocabulary tests check invariants (unique valid slugs, category order), not counts or wording.

## Global Constraints

- App name and domain come from one config value: `packages/shared/src/brand.ts` (spec header).
- API is versioned under `/api/v1`; all input and output validated with zod schemas from `@mymeetingapp/shared` (spec §7).
- Errors return `{ error: { code, message } }` with plain-language messages the app can show directly (spec §7).
- Never log request headers or bodies; error handlers log only the error itself (spec §2).
- Database access: Drizzle ORM with `pg` against the pooled `DATABASE_URL`, pool attached with `attachDatabasePool`; migrations use `DATABASE_URL_UNPOOLED` and never run on app startup (spec §12).
- Previews never use production data; preview branches come from a `seed` Neon branch (spec §12).
- Tags are never hard-deleted; retired tags stay in the table (spec §5).
- Starter vocabulary is exactly the 26 tags in spec §5, including "Old-timers".
- No analytics, no cookies, no tracking in anything added (spec §2).
- Secrets live only in Vercel environment variables; `.env*` files are git-ignored except `.env.example` (spec §12).
- Migrations must be backward-compatible with the previous deployment (add columns/tables first, remove later), because they run before the new code goes live.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

## Review Focus

1. **Version comparison as strings.** `"1.10.0"` must count as newer than `"1.9.0"`, or users get wrongly forced to upgrade. Pinned in Task 1 (`compareVersions`).
2. **Missing or malformed version env vars.** An unset or typo'd `MIN_VERSION_IOS` must not force every user to upgrade or crash `/config`; it falls back to `0.0.0` (never force). Pinned in Task 6.
3. **Re-running the seed after an admin retired a tag.** The seed must not bring a retired tag back. Pinned in Task 4.
4. **Retired tags and ordering in `/vocabulary`.** Retired tags must not appear, and the order must be stable (category order, then sort order) so the app's grouped picker doesn't shuffle. Pinned in Task 5.
5. **Building without a database.** `next build` must succeed with no `DATABASE_URL` (CI and fresh preview builds), so no route may query at build time. Pinned in Task 3 (build check) and Task 7 (CI step).

`packages/shared/src/version.ts`:

```ts
import { z } from "zod";

export const SemVer = z.string().regex(/^\d+\.\d+\.\d+$/, "Expected a version like 1.2.3");

function parse(version: string): [number, number, number] {
  if (!/^\d+\.\d+\.\d+$/.test(version)) throw new Error(`Invalid version: ${version}`);
  const [major, minor, patch] = version.split(".").map(Number) as [number, number, number];
  return [major, minor, patch];
}

export function compareVersions(a: string, b: string): -1 | 0 | 1 {
  const pa = parse(a);
  const pb = parse(b);
  for (let i = 0; i < 3; i++) {
    const diff = pa[i]! - pb[i]!;
    if (diff !== 0) return diff < 0 ? -1 : 1;
  }
  return 0;
}

export function isBelowVersion(version: string, minimum: string): boolean {
  return compareVersions(version, minimum) < 0;
}
```

```ts
import { ERROR_MESSAGES, type ErrorCode } from "@mymeetingapp/shared";

export const CACHE = {
  vocabulary: "public, s-maxage=3600, stale-while-revalidate=86400",
  config: "public, s-maxage=300, stale-while-revalidate=600",
} as const;

const STATUS: Record<ErrorCode, number> = {
  invalid_request: 400,
  too_many_tags: 400,
  unknown_tag: 400,
  attestation_failed: 401,
  tags_disabled: 403,
  device_blocked: 403,
  meeting_not_found: 404,
  not_tagged: 404,
  window_closed: 409,
  already_tagged: 409,
  upgrade_required: 426,
  rate_limited: 429,
  server_error: 500,
};

export function json(data: unknown, cacheControl = "no-store"): Response {
  return Response.json(data, { headers: { "Cache-Control": cacheControl } });
}

export function apiError(code: ErrorCode): Response {
  return Response.json(
    { error: { code, message: ERROR_MESSAGES[code] } },
    { status: STATUS[code], headers: { "Cache-Control": "no-store" } },
  );
}

// Logs only the error itself. Never log the request: headers carry raw device IDs.
export function withErrors<A extends unknown[]>(
  handler: (...args: A) => Promise<Response>,
): (...args: A) => Promise<Response> {
  return async (...args: A) => {
    try {
      return await handler(...args);
    } catch (err) {
      console.error(
        "[api] unhandled error:",
        err instanceof Error ? (err.stack ?? err.message) : String(err),
      );
      return apiError("server_error");
    }
  };
}
```

`apps/web/src/db/seed-vocabulary.ts`:

```ts
import { sql } from "drizzle-orm";
import { STARTER_VOCABULARY } from "@mymeetingapp/shared";
import { db, type Db } from "./client";
import { tags } from "./schema";

// Upserts label, category and order by slug. Never touches status, so retired tags stay retired.
export async function seedVocabulary(database: Db = db): Promise<{ upserted: number }> {
  const rows = STARTER_VOCABULARY.map((tag, index) => ({
    slug: tag.slug,
    label: tag.label,
    category: tag.category,
    sortOrder: index,
  }));
  await database
    .insert(tags)
    .values(rows)
    .onConflictDoUpdate({
      target: tags.slug,
      set: {
        label: sql`excluded.label`,
        category: sql`excluded.category`,
        sortOrder: sql`excluded.sort_order`,
      },
    });
  return { upserted: rows.length };
}
```

```ts
import { asc, eq, sql } from "drizzle-orm";
import { TAG_CATEGORIES, type VocabularyTag } from "@mymeetingapp/shared";
import { db, type Db } from "@/db/client";
import { tags } from "@/db/schema";

const categoryOrder = sql.raw(`array[${TAG_CATEGORIES.map((c) => `'${c}'`).join(", ")}]::text[]`);

export async function getActiveVocabulary(database: Db = db): Promise<VocabularyTag[]> {
  return database
    .select({ slug: tags.slug, label: tags.label, category: tags.category })
    .from(tags)
    .where(eq(tags.status, "active"))
    .orderBy(sql`array_position(${categoryOrder}, ${tags.category})`, asc(tags.sortOrder));
}
```

`apps/web/src/server/app-config.ts`:

```ts
import { SemVer, type AppConfigResponse } from "@mymeetingapp/shared";

type Env = Record<string, string | undefined>;

function version(env: Env, name: string): string {
  const raw = env[name]?.trim();
  if (!raw) return "0.0.0";
  if (SemVer.safeParse(raw).success) return raw;
  console.warn(`[config] ${name} is not a version like 1.2.3; using 0.0.0`);
  return "0.0.0";
}

const enabled = (env: Env, name: string) => env[name]?.trim().toLowerCase() !== "off";

export function readAppConfig(env: Env = process.env): AppConfigResponse {
  return {
    minSupportedVersion: {
      ios: version(env, "MIN_VERSION_IOS"),
      android: version(env, "MIN_VERSION_ANDROID"),
    },
    latestVersion: {
      ios: version(env, "LATEST_VERSION_IOS"),
      android: version(env, "LATEST_VERSION_ANDROID"),
    },
    features: { tagging: enabled(env, "FEATURE_TAGGING"), suggestions: enabled(env, "FEATURE_SUGGESTIONS") },
  };
}
```
