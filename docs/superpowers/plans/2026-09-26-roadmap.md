# mymeetingapp Build Roadmap

**Spec:** `SPEC.md` (v2, approved 2026-09-26)

The spec spans three independent systems (web/API, mobile app, feed discovery tool), so it is built as seven phases. Each phase gets its own detailed implementation plan in this folder, written when the previous phase has landed so it matches the real code. Each phase ends with something testable.

## Phase scopes

### Phase 1: Foundation

Spec §1, §7 (`/config`, `/vocabulary`, error envelope), §12. Detailed plan: `2026-09-26-phase-1-foundation.md`.

### Phase 2: Meeting data

Spec §3, §7 (search, online, detail, sync cron).

- Tables: `feeds`, `feed_meetings` (unique `feed_id, source_slug, day`), `meetings` (canonical, PostGIS `geography(Point,4326)`, `tags_disabled`, `archived_at`).
- Parsers: TSML/Meeting Guide JSON (shared), BMLT, Google Sheet; field allowlist; time zone from feed or coordinates.
- Canonical matching (same day + time, same normalized address or within 50 m), highest-priority source wins display fields, archive rather than delete.
- Sync runner: stalest feeds first, ~240 s budget, per-host 1 req/s, conditional requests, per-feed error isolation; cron every 15 minutes in `vercel.ts`.
- Census geocoding for missing coordinates.
- `POST /api/v1/meetings/search` (validated 2-decimal rounding, `ST_DWithin`, max 1000, Runtime Cache), `GET /meetings/online` (dedup by conference URL), `GET /meetings/:id`.
- Tag counts are empty until Phase 3, but the response shape includes them from the start.

### Phase 3: Tagging

Spec §2 (ID derivation), §5, §6 (except platform attestation), §7 (tag, suggestion, delete-mine, maintenance endpoints).

- HKDF key derivation from `DEVICE_ID_PEPPER`; `device_hash`, `submitter_id`.
- Tables: `devices`, `tag_submissions`, `tag_counts`, `tag_audit`, `rate_limits`, `suggestions`, `ai_decisions`, `attest_challenges`.
- DST-aware tagging window in the meeting's time zone.
- Write-request header parsing; attestation verifier interface with a no-op implementation while `REQUIRE_ATTESTATION` is off.
- AI screening through Vercel AI Gateway (zero data retention, model from `SUGGESTION_MODEL`).
- Nightly maintenance cron: recount, 180-day expiry, purges.
- Swing detection, block device (recompute submitter IDs across all meetings).

### Phase 4: Website + metrics

Spec §9, §10, §13 (privacy policy text).

- Atkinson Hyperlegible via `next/font`, light/dark, static pages, footer disclaimer, `robots.txt`, sitemap, Open Graph, `MobileApplication` structured data.
- Privacy policy written from the §13 data inventory, with a test that fails if the inventory and policy drift.
- `proxy.ts` Basic Auth (constant-time compare, login rate limit), `noindex`, `no-store`; metrics server components; admin Server Actions.
- Connect mymeetingapp.com.

### Phase 5: Mobile app

Spec §8.

- Expo dev build, Expo Router, `expo-sqlite`, `expo-secure-store`, react-native-maps, `expo-location`.
- API client validated with shared zod schemas.
- Proxy-verified network audit (acceptance criteria for location and personal data).

### Phase 6: Integrity + stores

Spec §6 (App Attest, DeviceCheck, Play Integrity), §11.

- Native modules or maintained Expo modules; server verification; flip `REQUIRE_ATTESTATION` on in production.
- iOS privacy manifest, purpose strings, Android permissions; App Privacy label and Data safety form from §13; age ratings; listings.

### Phase 7: Feed discovery

Spec §4.

- Politeness layer (robots.txt, 1 req/s/host, User-Agent with contact email, timeouts, no retry storms).
- Detection order, verification, restricted handling, `registry.yaml`, `coverage.md`, seed into `feeds`, monthly workflow opening a PR.

## Acceptance criteria → phase

| Spec §14 criterion                                                      | Phase                       |
| ----------------------------------------------------------------------- | --------------------------- |
| Fresh install finds meetings with no account and no location permission | 5 (API in 2)                |
| Only rounded coordinates, only in search bodies; none in URLs, logs, DB | 2 (server), 5 (proxy audit) |
| Rejections: outside window, second submission in 7 days, unknown tags   | 3                           |
| Edit/delete any time with updated counts                                | 3                           |
| New tag shows immediately with count 1; once per distinct device        | 3                           |
| Different submitter IDs per meeting; no link after 7 days               | 3                           |
| delete-mine removes everything for the device                           | 3                           |
| Personal data never in network traffic                                  | 5                           |
| `/metrics` 401 without credentials, totals only, CSRF-safe              | 4                           |
| Discovery registry + coverage report, restricted skipped                | 7                           |
| Failing feed isolated and shown on `/metrics`                           | 2 (isolation), 4 (display)  |
| Slug change keeps canonical meeting and tags                            | 2                           |
| No personal contact fields stored or returned                           | 2                           |
| Below-minimum app shows upgrade screen, offline data still works        | 1 (`/config`), 5 (app)      |
| Every privacy policy statement maps to §13 and code                     | 4                           |
